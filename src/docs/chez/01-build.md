# 1. Building and running

## 1.1 Chez Scheme

Any installation of Chez Scheme 10.4 with its "machine directory", which
holds `scheme.h`, `libkernel.a` (with `liblz4.a` and `libz.a`) and the heap
images `petite.boot` and `scheme.boot`. On macOS, `brew install chezscheme`
gives `/opt/homebrew/lib/csv10.4.1/tarm64osx`.

`configure` finds the machine directory from the `chez` (or `scheme`)
executable on the `PATH`; `--with-chez=DIR` gives it otherwise
(`misc/m4/scheme.m4`, `LC_CHEZ`). Chez is linked statically; the heap images
are read at start-up from that directory, or from `$SCHEMEHEAPDIRS`.

## 1.2 Configuring and building

```sh
cd src
./configure --with-scheme=chez \
  'CPPFLAGS=-I/opt/homebrew/opt/libpng/include/libpng16 -I/opt/homebrew/include' \
  'LDFLAGS=-L/opt/homebrew/lib -L/opt/homebrew/opt/libpng/lib'
make -j8
```

This is the Qt build; the other options of `configure` are unchanged. The
glue is generated by Chez itself: when the specifications of the glue
change, `make` runs `chez --script src/Scheme/Chez/build-glue-chez.scm .`,
which writes `src/Scheme/Chez/glue_chez.cpp` and
`TeXmacs/progs/kernel/boot/glue-chez.scm` (both are committed).

## 1.3 Compiling the Scheme modules and the boot image

`make` builds the binary only. The Scheme code is compiled in two more steps,
which have to be run again after a change of `TeXmacs/progs` (or of the glue):

```sh
export TEXMACS_PATH=$PWD/TeXmacs TEXMACS_BOOT_PATH=$PWD/TeXmacs/boot
export TEXMACS_HOME_PATH=<a scratch folder> QT_QPA_PLATFORM=offscreen
./TeXmacs/bin/texmacs.bin -recompile-modules      # all the modules
chez --script src/Scheme/Chez/make-boot.scm TeXmacs/boot TeXmacs/boot/texmacs.boot
```

- `-compile-modules` recompiles the modules whose source changed;
  `-recompile-modules` (or `TEXMACS_RECOMPILE_ALL=1`) all of them. A full
  compilation of the 488 modules takes about 16 s, the boot image 2 s
  (macOS, Apple silicon).
- The compiler writes the transpiled sources and the compiled modules (`.so`)
  under `$TEXMACS_BOOT_PATH`. Set it: without it the compiler writes to
  `build-texmacos/boot` (the layout of the original CMake build), while
  TeXmacs looks in `$TEXMACS_PATH/boot`.
- `make-boot.scm` packs the 177 modules of the start-up (its list
  `*startup-boot-modules*`) into `texmacs.boot`; the other modules are
  loaded from their `.so` when they are first used.
- `TeXmacs/boot/` is ignored by git.

## 1.4 Running

```sh
TEXMACS_PATH=$PWD/TeXmacs ./TeXmacs/bin/texmacs.bin
```

At start-up TeXmacs registers Chez's heap images and, when it finds one,
`texmacs.boot` (in `$TEXMACS_BOOT_PATH`, else `$TEXMACS_PATH/boot`). Chez
builds its heap from them; `boot/init-texmacs-boot-file.so` then finishes the
start-up, through the shared `init-kernel.scm` and `init-texmacs.scm`.
Without a boot image (or with `TEXMACS_NO_BOOT=1`), `init-texmacs-chez.scm`
loads the compiled modules one by one, then the same two files.

Environment variables:

| Variable | Effect |
|---|---|
| `TEXMACS_BOOT_PATH` | where the compiled modules and `texmacs.boot` are (default `$TEXMACS_PATH/boot`) |
| `TEXMACS_BOOT_FILE` | another boot image |
| `TEXMACS_NO_BOOT=1` | start without the boot image, from the `.so` files |
| `SCHEMEHEAPDIRS` | where Chez's own heap images are |
| `TEXMACS_RECOMPILE_ALL=1` | the compiler recompiles every module |
| `TM_GLUE_TRACE=1` | the Scheme frames of a glue routine which fails |
| `TEXMACS_TRACE_VERBOSE=1` | with `TEXMACS_NO_BOOT`: print each module as it is loaded |
| `TEXMACS_DUMP_BOOT_ORDER=FILE` | with `TEXMACS_NO_BOOT`: write the order in which the modules were loaded to `FILE` (`TEXMACS_TRACE_MODULES=1`: to `$TEXMACS_BOOT_PATH/boot-order.scm`) |

## 1.5 Tests

The regression suites run as with the other Schemes, for instance
`tests/scheme/check.sh typeset` or, for all of them,

```sh
texmacs.bin -x '(exit (catch #t (lambda () (use-modules (check check-master))
                  (min 1 (run-all-tests))) (lambda args 2)))' -q
```

with `QT_QPA_PLATFORM=offscreen` and a scratch `TEXMACS_HOME_PATH`. The test
modules are compiled with the others: after changing a test, compile the
modules again. All 43 suites pass.
